## 1. 服务概述

### 1.1 服务定位

策略中心是Agent人机委托机制的核心服务，负责委托策略的配置、存储、查询和管理。作为独立的微服务，策略中心提供RESTful API供Agent Gateway和MCP Gateway调用。

### 1.2 核心职责

**主要职责**：
- 委托策略配置管理：创建、更新、删除、查询委托策略
- 委托关系管理：建立、维护、解除委托关系
- 工具标签管理：管理工具分类、标签、元数据
- 策略模板管理：提供策略模板库，简化用户配置
- 委托链解析：解析多级委托链，计算有效权限范围
- 实时确认管理：管理实时确认规则和确认记录
- 审计日志查询：提供委托相关审计日志查询接口

**边界职责**：
- 不负责Token生成（Agent Gateway职责）
- 不负责Cookie还原（MCP Gateway职责）
- 不负责工具调用（MCP Gateway职责）
- 不负责Agent注册（Agent Gateway职责）

### 1.3 服务依赖

**上游服务**：
- IDaaS认证服务：获取用户身份信息
- B2B Admin Service：获取应用、租户、数据源信息

**下游服务**：
- Agent Gateway：提供委托策略查询接口
- MCP Gateway：提供工具权限查询接口
- Elasticsearch：审计日志存储
- MySQL：委托策略持久化存储
- Redis：委托策略缓存

### 1.4 技术栈

**核心技术**：
- Java 21
- Spring Boot 3.4.6
- Spring Framework 6.2.11
- Spring Security 6.4.10
- Jakarta EE（jakarta.* namespace）
- MySQL 8.3.0（持久化存储）
- Redis 7.2（缓存）
- Elasticsearch 8.18.1（审计日志）
- Lombok 1.18.32
- Fastjson 1.2.83

**可选技术**：
- Neo4j 5.x（委托关系图存储，P3特性）
- Drools 8.x（规则引擎，P2特性）
- Aviator 5.x（表达式引擎，P2特性）

**P0核心功能**：
- 必须实现，系统核心能力

## 3. 详细设计

### 3.1 P0核心功能详细设计

#### 3.1.1 P0-001：委托策略创建

**功能描述**：
支持用户创建委托策略，配置Agent的权限范围、数据范围、有效期等。

**业务规则**：
1. 委托策略必须指定委托人（userId）和受托人（agentId）
2. 委托类型必须明确：长期委托、临时委托、会话委托
3. 权限范围必须配置：工具标签组合或具体工具列表
4. 数据范围可选配置：租户、应用、数据源限制
5. 有效期必须配置：长期委托无期限，临时委托指定期限，会话委托单次有效
6. 确认规则可选配置：敏感工具实时确认规则
7. 委托策略创建后立即生效

**数据结构**：
```java
@Data
public class DelegationPolicy {
    private String delegationId;
    private String userId;
    private String agentId;
    private DelegationType delegationType;
    private PermissionScope permissionScope;
    private DataScope dataScope;
    private Date effectiveTime;
    private Date expiryTime;
    private ConfirmationRule confirmationRule;
    private DelegationStatus status;
    private Date createTime;
    private Date updateTime;
    private String createdBy;
    private String updatedBy;
}

@Data
public class PermissionScope {
    private List<String> toolTags;
    private List<String> toolNames;
    private List<ToolPermission> toolPermissions;
}

@Data
public class DataScope {
    private List<String> tenantIds;
    private List<String> appNames;
    private List<String> datasourceIds;
}

@Data
public class ConfirmationRule {
    private ConfirmationType confirmationType;
    private List<String> requireConfirmationTools;
    private Integer confirmationTimeout;
}
```

**接口设计**：
```
POST /api/v1/delegations
Content-Type: application/json

Request Body:
{
  "userId": "l00867517",
  "agentId": "agent-001",
  "delegationType": "LONG_TERM",
  "permissionScope": {
    "toolTags": ["datasource", "integrationtask"],
    "toolNames": ["datasource_create", "datasource_query"]
  },
  "dataScope": {
    "tenantIds": ["1111111111111111"],
    "appNames": ["C00001-O0023"]
  },
  "effectiveTime": "2026-06-04T00:00:00Z",
  "expiryTime": null,
  "confirmationRule": {
    "confirmationType": "REAL_TIME",
    "requireConfirmationTools": ["datasource_delete"],
    "confirmationTimeout": 30
  }
}

Response:
{
  "delegationId": "del-uuid-001",
  "status": "ACTIVE",
  "createTime": "2026-06-04T10:00:00Z"
}
```

**流程设计**：
```
流程1：委托策略创建流程
1. 接收委托策略创建请求
2. 验证请求参数完整性
3. 验证用户身份（从JWT Token获取userId）
4. 验证Agent存在性（调用Agent Gateway查询接口）
5. 验证权限范围合法性（工具标签或工具名称必须存在）
6. 验证数据范围合法性（租户、应用必须存在）
7. 生成委托ID（UUID）
8. 设置委托状态为ACTIVE
9. 设置创建时间和创建人
10. 持久化委托策略到MySQL
11. 缓存委托策略到Redis
12. 记录审计日志到Elasticsearch
13. 返回委托ID和状态
```

**异常处理**：
```
异常1：参数缺失
- 异常代码：SC4001
- 异常信息：Required parameter missing: {parameterName}
- 处理方式：返回400错误，提示用户补充参数

异常2：Agent不存在
- 异常代码：SC4002
- 异常信息：Agent not found: {agentId}
- 处理方式：返回404错误，提示用户Agent不存在

异常3：工具标签不存在
- 异常代码：SC4003
- 异常信息：Tool tag not found: {toolTag}
- 处理方式：返回400错误，提示用户工具标签不存在

异常4：数据范围非法
- 异常代码：SC4004
- 异常信息：Invalid data scope: tenantId {tenantId} not found
- 处理方式：返回400错误，提示用户数据范围非法

异常5：委托策略冲突
- 异常代码：SC4005
- 异常信息：Delegation policy conflict: existing policy for user {userId} and agent {agentId}
- 处理方式：返回409错误，提示用户委托策略已存在
```

**性能要求**：
- 创建延迟：< 100ms
- 创建吞吐量：> 100 TPS
- 数据库写入：< 50ms
- 缓存写入：< 10ms

**测试用例**：
```

- 输入：完整的委托策略参数
- 预期：委托策略创建成功，返回委托ID，状态为ACTIVE

测试用例2：创建临时委托策略
- 输入：指定有效期的委托策略参数
- 预期：委托策略创建成功，有效期正确设置

测试用例3：创建会话委托策略
- 输入：会话类型的委托策略参数
- 预期：委托策略创建成功，单次有效

测试用例4：参数缺失
- 输入：缺少必填参数
- 预期：返回400错误，提示参数缺失

测试用例5：Agent不存在
- 输入：不存在的agentId
- 预期：返回404错误，提示Agent不存在

测试用例6：工具标签不存在
- 输入：不存在的工具标签
- 预期：返回400错误，提示工具标签不存在

测试用例7：委托策略冲突
- 输入：已存在的userId和agentId组合
- 预期：返回409错误，提示委托策略已存在

#### 3.1.2 P0-002：委托策略查询

**功能描述**：
支持查询委托策略详情，供Agent Gateway和MCP Gateway调用，验证委托权限。

**业务规则**：
1. 支持按委托ID查询策略详情
2. 支持按userId和agentId查询策略详情
3. 支持批量查询多个委托策略
4. 优先从缓存查询，缓存未命中则查询数据库
5. 查询结果包含完整的策略配置
6. 查询结果包含策略状态和有效期信息

**接口设计**：
```
接口1：按委托ID查询
GET /api/v1/delegations/{delegationId}

Response:
{
  "delegationId": "del-uuid-001",
  "userId": "l00867517",
  "agentId": "agent-001",
  "delegationType": "LONG_TERM",
  "permissionScope": {
    "toolTags": ["datasource", "integrationtask"],
    "toolNames": ["datasource_create", "datasource_query"]
  },
  "dataScope": {
    "tenantIds": ["1111111111111111"],
    "appNames": ["C00001-O0023"]
  },
  "effectiveTime": "2026-06-04T00:00:00Z",
  "expiryTime": null,
  "status": "ACTIVE",
  "createTime": "2026-06-04T10:00:00Z"
}

接口2：按userId和agentId查询
GET /api/v1/delegations?userId={userId}&agentId={agentId}

Response:
[
  {
    "delegationId": "del-uuid-001",
    "userId": "l00867517",
    "agentId": "agent-001",
    ...
  }
]

接口3：批量查询
POST /api/v1/delegations/batch-query
Content-Type: application/json

Request Body:
{
  "delegationIds": ["del-uuid-001", "del-uuid-002"]
}

Response:
{
  "del-uuid-001": {
    "delegationId": "del-uuid-001",
    ...
  },
  "del-uuid-002": {
    "delegationId": "del-uuid-002",
    ...
  }
}
```

**流程设计**：
```
流程1：按委托ID查询流程
1. 接收委托ID查询请求
2. 验证委托ID格式
3. 查询Redis缓存（Key: delegation:{delegationId})
4. 缓存命中则返回缓存数据
5. 缓存未命中则查询MySQL数据库
6. 数据库查询成功则缓存到Redis
7. 返回委托策略详情

流程2：按userId和agentId查询流程
1. 接收userId和agentId查询请求
2. 验证userId和agentId格式
3. 查询Redis缓存（Key: delegation:{userId}:{agentId})
4. 缓存命中则返回缓存数据
5. 缓存未命中则查询MySQL数据库
6. 数据库查询成功则缓存到Redis
7. 返回委托策略列表

流程3：批量查询流程
1. 接收批量查询请求
2. 验证委托ID列表格式
3. 批量查询Redis缓存
4. 缓存未命中的委托ID查询数据库
5. 数据库查询成功则批量缓存到Redis
6. 返回委托策略映射
```

**性能要求**：
- 单次查询延迟：< 10ms（缓存命中），< 50ms（缓存未命中）
- 批量查询延迟：< 100ms（100个委托策略）
- 缓存命中率：> 95%

**测试用例**：
```
测试用例1：按委托ID查询成功
- 输入：存在的委托ID
- 预期：返回委托策略详情，数据正确

测试用例2：按委托ID查询不存在
- 输入：不存在的委托ID
- 预期：返回404错误，提示委托策略不存在

测试用例3：按userId和agentId查询成功
- 输入：存在的userId和agentId
- 预期：返回委托策略列表，数据正确

测试用例4：批量查询成功
- 输入：多个存在的委托ID
- 预期：返回委托策略映射，数据正确

测试用例5：批量查询部分不存在
- 输入：部分存在的委托ID
- 预期：返回存在的委托策略，不存在的返回null

#### 3.1.3 P0-003：委托策略更新

**功能描述**：
支持更新委托策略，修改权限范围、数据范围、有效期等。

**业务规则**：
1. 只能更新自己的委托策略（userId必须匹配）
2. 委托策略状态必须为ACTIVE才能更新
3. 更新权限范围时，验证新权限范围合法性
4. 更新数据范围时，验证新数据范围合法性
5. 更新有效期时，验证新有效期合法性
6. 更新后立即生效，刷新缓存
7. 记录更新历史，支持审计追溯

**接口设计**：
```
PUT /api/v1/delegations/{delegationId}
Content-Type: application/json

Request Body:
{
  "permissionScope": {
    "toolTags": ["datasource", "integrationtask", "monitor"],
    "toolNames": ["datasource_create", "datasource_query", "monitor_config"]
  },
  "dataScope": {
    "tenantIds": ["1111111111111111", "2222222222222222"],
    "appNames": ["C00001-O0023", "C00002-O0024"]
  },
  "expiryTime": "2026-12-31T23:59:59Z",
  "confirmationRule": {
    "confirmationType": "BATCH",
    "requireConfirmationTools": ["datasource_delete", "integrationtask_delete"],
    "confirmationTimeout": 60
  }
}

Response:
{
  "delegationId": "del-uuid-001",
  "status": "ACTIVE",
  "updateTime": "2026-06-04T11:00:00Z"
}
```

**流程设计**：

#### 3.1.8 P0-008：策略缓存管理

**功能描述**：
支持策略缓存，提升查询性能，保证缓存一致性。

**业务规则**：
1. 使用Redis作为缓存存储
2. 缓存Key设计：delegation:{delegationId}、delegation:{userId}:{agentId}
3. 缓存过期时间：30分钟
4. 缓存更新策略：主动更新（策略变更时）、被动更新（缓存过期时）
5. 缓存删除策略：策略删除时立即删除缓存
6. 缓存预热：系统启动时预热热点策略
7. 缓存监控：监控缓存命中率、缓存大小

**缓存设计**：
```
缓存Key设计：
1. 委托策略缓存：
   - Key: delegation:{delegationId}
   - Value: DelegationPolicy JSON
   - TTL: 30分钟

2. 用户Agent委托缓存：
   - Key: delegation:{userId}:{agentId}
   - Value: List<DelegationPolicy> JSON
   - TTL: 30分钟

3. 工具标签缓存：
   - Key: tool:tags
   - Value: Map<String, ToolTag> JSON
   - TTL: 1小时

4. 工具元数据缓存：
   - Key: tool:{toolName}:metadata
   - Value: ToolMetadata JSON
   - TTL: 1小时

缓存更新策略：
1. 主动更新：
   - 委托策略创建时：写入缓存
   - 委托策略更新时：刷新缓存
   - 委托策略删除时：删除缓存
   - 工具标签同步时：刷新缓存

2. 被动更新：
   - 缓存过期时：重新查询数据库并缓存

3. 缓存预热：
   - 系统启动时：预热最近1000个活跃委托策略
```

**流程设计**：
```
流程1：缓存写入流程
1. 委托策略创建/更新成功
2. 序列化委托策略为JSON
3. 写入Redis缓存（Key: delegation:{delegationId})
4. 写入Redis缓存（Key: delegation:{userId}:{agentId})
5. 设置TTL为30分钟

流程2：缓存查询流程
1. 查询委托策略
2. 先查询Redis缓存
3. 缓存命中则返回缓存数据
4. 缓存未命中则查询MySQL
5. 查询成功则写入缓存
6. 返回查询结果

流程3：缓存删除流程
1. 委托策略删除成功
2. 删除Redis缓存（Key: delegation:{delegationId})
3. 删除Redis缓存（Key: delegation:{userId}:{agentId})
4. 返回删除结果

流程4：缓存预热流程
1. 系统启动时触发缓存预热
2. 查询最近1000个活跃委托策略
3. 批量写入Redis缓存
4. 记录预热日志
```

**性能要求**：
- 缓存命中率：> 95%

- 缓存写入延迟：< 10ms
- 缓存预热时间：< 30秒

## 6. 流程设计

### 6.1 核心流程

#### 6.1.1 委托策略创建流程

```
流程步骤：
1. 接收委托策略创建请求
2. 验证请求参数完整性
   - 必填参数：userId、agentId、delegationType、permissionScope、effectiveTime
   - 可选参数：dataScope、expiryTime、confirmationRule
3. 验证用户身份
   - 从JWT Token获取userId
   - userId必须与请求参数中的userId一致
4. 验证Agent存在性
   - 调用Agent Gateway查询接口：GET /api/v1/agents/{agentId}
   - Agent必须存在且状态为ACTIVE
5. 验证权限范围合法性
   - 工具标签必须存在：查询tool_metadata表
   - 工具名称必须存在：查询tool_metadata表
6. 验证数据范围合法性
   - 租户ID必须存在：调用B2B Admin Service查询接口
   - 应用名称必须存在：调用B2B Admin Service查询接口
7. 检测委托策略冲突
   - 查询是否存在userId+agentId的委托策略
   - 存在则返回冲突错误
8. 生成委托ID
   - UUID格式：del-{uuid}
9. 设置委托状态
   - 状态：ACTIVE
10. 设置创建时间和创建人
    - createTime：当前时间
    - createdBy：userId
11. 持久化委托策略到MySQL
    - 插入delegation_policy表
12. 缓存委托策略到Redis
    - Key: delegation:{delegationId}
    - Key: delegation:{userId}:{agentId}
13. 记录审计日志到Elasticsearch
    - 操作类型：CREATE
    - 操作详情：委托策略创建
14. 返回委托ID和状态

性能要求：
- 总延迟：< 100ms
- 数据库写入：< 50ms
- 缓存写入：< 10ms
- 审计日志写入：< 20ms（异步）
```

#### 6.1.2 委托权限验证流程

```
流程步骤：
1. 接收权限验证请求
2. 验证请求参数完整性
   - 必填参数：userId、agentId、toolName
   - 可选参数：dataContext（tenantId、appName）
3. 查询委托策略
   - 先查询Redis缓存：Key: delegation:{userId}:{agentId}
   - 缓存未命中则查询MySQL：SELECT * FROM delegation_policy WHERE user_id=? AND agent_id=? AND status='ACTIVE'
   - 缓存查询结果
4. 验证委托策略存在性
   - 不存在则返回hasPermission=false
5. 验证委托策略状态
   - 状态必须为ACTIVE
   - 非ACTIVE则返回hasPermission=false
6. 验证委托策略有效期
   - expiryTime必须大于当前时间或为null
   - 已过期则返回hasPermission=false
7. 验证工具权限
   - 工具名称在toolNames列表中，或
   - 工具标签在toolTags列表中
   - 无权限则返回hasPermission=false
8. 验证数据范围
   - tenantId在tenantIds列表中，或tenantIds为空（不限）
   - appName在appNames列表中，或appNames为空（不限）
   - 不匹配则返回hasPermission=false
9. 判断是否需要实时确认
   - 工具在requireConfirmationTools列表中
   - 需要确认则返回requireConfirmation=true
10. 返回验证结果
    - hasPermission：true/false
    - delegationId：委托ID
    - permissionScope：权限范围
    - dataScope：数据范围
    - requireConfirmation：是否需要确认
    - confirmationRule：确认规则

性能要求：
- 总延迟：< 10ms
- 缓存查询：< 5ms
- 数据库查询：< 20ms（缓存未命中时）
```

#### 6.1.3 委托链解析流程

```
流程步骤：
1. 接收委托链解析请求
2. 验证委托链格式
   - 委托链必须是数组
   - 每个元素包含from、to、delegationId
3. 验证委托链起点
   - 第一个元素的from必须是user:{userId}
   - 非user起点则返回valid=false
4. 验证委托链终点
   - 最后一个元素的to必须是当前Agent
   - 非当前Agent则返回valid=false
5. 验证委托链连续性
   - 每个元素的to必须等于下一个元素的from
   - 不连续则返回valid=false
6. 批量查询所有委托策略
   - 提取所有delegationId
   - 批量查询委托策略（优先缓存）
7. 验证所有委托策略有效性
   - 状态必须为ACTIVE
   - 有效期未过期
   - 任一无效则返回valid=false
8. 计算有效权限范围
   - toolTags交集：所有委托策略的toolTags交集
   - toolNames交集：所有委托策略的toolNames交集
9. 计算有效数据范围
   - tenantIds交集：所有委托策略的tenantIds交集
   - appNames交集：所有委托策略的appNames交集
10. 计算有效确认规则
    - confirmationType取最严格：REAL_TIME > BATCH > NONE
    - requireConfirmationTools合并：所有委托策略的工具列表合并
    - confirmationTimeout取最小值
11. 返回解析结果
    - chainId：委托链ID
    - valid：true/false
    - effectivePermissionScope：有效权限范围
    - effectiveDataScope：有效数据范围
    - effectiveConfirmationRule：有效确认规则

性能要求：
- 总延迟：< 20ms（3级委托链）
- 批量查询：< 10ms
- 交集计算：< 5ms
```

## 12. 附录

### 12.1 术语表

| 术语 | 定义 |
|-----|------|
| 委托策略 | 用户委托Agent的策略配置，包含权限范围、数据范围、有效期等 |
| 委托链 | 多级委托关系的链式结构，如user→agent-001→agent-002 |
| 权限范围 | Agent可执行的工具范围，包含工具标签或工具名称列表 |
| 数据范围 | Agent可访问的数据范围，包含租户、应用、数据源限制 |
| 确认规则 | Agent调用敏感工具时需要用户确认的规则 |
| 工具标签 | 工具的分类标签，用于策略配置 |
| 工具元数据 | 工具的详细信息，包含参数、返回值、示例等 |
| 策略模板 | 预定义的策略配置模板，简化用户配置 |
| 策略版本 | 策略的历史版本，支持版本管理和回滚 |
